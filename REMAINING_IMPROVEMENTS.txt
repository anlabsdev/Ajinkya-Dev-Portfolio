1. 3D MODEL FILE SIZE (attempted, reverted — needs your call)
────────────────────────────────────────────────────────────────────
The 3D models are the single biggest thing hurting load time:

  bird.glb                              1.6 MB
  plane.glb                             1.5 MB
  island.glb                            352 KB
  sky.glb                               324 KB   (all 4 load on Home)
  low_poly_man_working_at_a_table.glb   1.4 MB   (Contact page)
  robot_hip_hop_dancing.glb             4.5 MB   (Chatbot page)
  deadpool_dancing.glb                  7.6 MB   (Thank-you page)

I ran `@gltf-transform/cli optimize --compress meshopt` on all seven.
Six shrank dramatically (bird -50%, deadpool -51%, low_poly_man -78%,
sky -80%, plane -34%); robot_hip_hop_dancing.glb actually grew and
should stay excluded. The compressed files passed structural validation
(gltf-transform validate: no errors), and your `useGLTF` calls already
auto-configure both Draco and Meshopt decoders (three-stdlib), so they
should Just Work in any real browser.

I could NOT verify this visually — the only headless browser available
in this environment crashed (renderer access violation) specifically
when loading the meshopt-compressed geometry under software rendering,
while the same page with the original files rendered fine. That's most
likely a sandbox/SwiftShader limitation, not a real browser issue, but
I won't ship an unverified change to the site's signature 3D hero.

To do this safely:
  1. Run: npx @gltf-transform/cli optimize <input> <output> --compress meshopt
     on each file above (skip robot_hip_hop_dancing.glb).
  2. Replace the files in src/assets/3d/.
  3. Run `npm run dev`, open the site in an actual browser (Chrome/Edge,
     not headless), and check: Home hero (bird/plane/island/sky spin
     and drag correctly), Contact page (low_poly_man walks/idles), and
     ThankYou page (deadpool dances) — all after form submit.
  4. If everything looks right, commit. If anything looks broken/missing,
     revert that one file only.

Potential savings if it works out: roughly 6-7 MB off total asset
weight, cutting Home page's critical model payload by ~40%.
